12-Week Roadmap · Python + Rust → AI Architect

Build a portfolio that proves
architecture judgment.

Not a tutorial series. An architecture apprenticeship in public: every sprint ships a repo, a decision record, and measured evidence. By day 90, a stranger should trust your AI architecture decisions within five minutes.

North star: an AI lead or client opens your GitHub and, in under 5 minutes, believes you can turn a vague AI idea into a bounded system — with evals, failure modes, a cost envelope, and a clear answer to “when not to use AI.”

Anchor: telecom NOC copilot over a Rust network codebase · local reproducible demos · under $50/month.

The two doors

Same body of work. Two entry paths.

Door 01 · Depth

The AI Lead

Wants to know you won’t set their AI project on fire.

  • ADRs and rejected options
  • System diagrams and boundaries
  • Eval design and failure modes
  • Cost / latency / risk tradeoffs
  • Threat model and blast radius
Must leave believing: this person can be trusted with an ambiguous AI problem.
Door 02 · Outcome

The Client

Wants proof it works, what it costs, and why it won’t break.

  • A working system and demo
  • Clear problem → outcome case study
  • Cost envelope in plain numbers
  • Runbook and postmortem
  • Honest limitations
Must leave believing: this person ships, and ships safely.

Day 1Problem, workloads, scaffold
  • Scaffold repo, dirs, Makefile, .env.example
  • Write README problem, audience, non-goals
  • Define 3 reference workloads: code Q&A, tool-use decision, structured extraction
  • Seed tasks.jsonl with 5 tasks, one per category
  • Create ADR-001 skeleton; open learning-log issue #1

Done when: Public repo pushed with README, 5 seed tasks, and ADR skeleton.

Day 2Provider interface + adapters
  • Define a Provider protocol and config loader
  • Implement 2–3 adapters (hosted and/or local)
  • Load keys from env; never commit secrets
  • Smoke-call each model on one prompt

Done when: One command reaches every candidate model.

Day 3First recorded run
  • Build the runner loop over tasks
  • Persist results.jsonl with run id, model, temperature, seed, timestamp
  • Capture errors without aborting the run

Done when: A committed run reproduces the same raw records.

Day 4Task set + deterministic scoring
  • Expand to 20–30 tasks across 5 categories
  • Freeze tasks.jsonl and tag a version
  • Implement exact-match and JSON-schema scoring
  • Add tests for the scorers

Done when: Score a known run and get the expected numbers.

Day 5Baseline + failure taxonomy
  • Run all models on the full task set
  • Report quality per category
  • Draft failure taxonomy: over-refusal, format drift, hallucination, truncation, wrong label, timeout
  • Open and close the week-1 learning-log issue

Done when: Baseline table exists and failures are named with examples.

Day 6Latency + cost instrumentation
  • Measure wall-clock p50/p95 per model
  • Count prompt and completion tokens
  • Add a price table and cost per 1k tasks
  • Normalize cost so models are comparable

Done when: Every row has latency and cost, not just quality.

Day 7Decision matrix report
  • Aggregate raw runs in report.py
  • Emit matrix: quality / p50 / p95 / cost / reliability
  • Add one chart
  • Test report generation

Done when: Report is generated from runs, never hand-typed.

Day 8Reproducibility hardening
  • Pin seeds and temperature
  • Add retries, timeouts, and backoff
  • Run from a clean clone using documented commands
  • Add CI to run tests and lint

Done when: A stranger reproduces your matrix with make setup && make run.

Day 9Analysis + ADR-001 + README
  • Compare tradeoffs and pick a model plus a fallback
  • Write ADR-001: context, drivers, evidence, decision, consequences, revisit triggers
  • Write README results and limitations
  • Add the when-not-to-use-an-LLM argument

Done when: ADR and README state a defended choice with linked evidence.

Day 10Polish + publish
  • Audit against the DoD checklist
  • Fix broken links and setup steps
  • Link the repo from the portfolio index
  • Close the week-2 log and run the sprint retro

Done when: Repo passes the DoD checklist and is publicly linked.

Day 1Codebase + question set
  • Pick a real Rust codebase you can read
  • Write 20–30 questions with expected evidence
  • Scaffold the repo and start ADR-002
  • Define index and query boundaries

Day 2Rust ingestion + chunking
  • Parse items (fn/struct/impl) with tree-sitter or syn
  • Chunk semantically and keep metadata: file, item, lines
  • Persist chunks

Done when: Every chunk traces back to a file and line range.

Day 3Embeddings + index build
  • Embed chunks with a chosen model
  • Build the vector index
  • Measure ingest time and cost

Done when: Index rebuilds from scratch with one command.

Day 4Python retrieval + citations
  • Implement retrieve → rerank → assemble → answer
  • Force citations to a chunk and source
  • Add a thin CLI or API

Done when: Answers cite real code locations.

Day 5Baseline retrieval eval
  • Run the frozen questions
  • Compute recall@k and groundedness
  • Log misses with root cause
  • Close the week-1 log

Done when: Baseline is measured, not asserted.

Day 6Hybrid search + reranking
  • Add BM25 plus vector hybrid
  • Add a reranker
  • A/B the change against baseline

Done when: You can show which change moved recall.

Day 7Retrieval eval suite
  • Formalize recall, precision, and faithfulness
  • Add a labeled set and a scorer
  • Store per-question results

Done when: The eval suite runs in CI or one command.

Day 8Cost + latency + caching
  • Instrument query cost and latency
  • Add caching for embeddings and answers
  • Budget the context window per query

Done when: Each query has a cost and latency number.

Day 9Failure analysis + ADR + demo
  • Analyze what retrieval misses and why
  • Write ADR-002: split, chunking, embedding, rerank
  • Record a cited demo

Done when: ADR defends the Rust/Python split with evidence.

Day 10Polish + publish
  • Audit DoD, reproduce, and link the index
  • Close the week-2 log and run the retro

Done when: Repo is publicly reproducible and linked.
